# QazaqProtocol — локальное протоколирование совещаний

Windows-приложение: загрузка аудио/видео или запись микрофона и системного звука →
стенограмма → черновик поручений и краткое саммари → DOCX/PDF/TXT.
Работает для произвольной организации; название и глоссарий задаются в настройках.

## Готовое приложение

Откройте `dist/QazaqProtocol-Local/QazaqProtocol.exe`.
На другой компьютер копируйте **всю папку** `QazaqProtocol-Local`, включая `_internal` и `models`.
Python и API-ключи пользователю не нужны. Требуется Windows x64 и WebView2 Runtime;
при недоступности WebView2 открывается локальный интерфейс в системном браузере.
Данные пользователя: `%LOCALAPPDATA%/QazaqProtocol/storage`, настройки: `settings.json` рядом с `storage`.
Подробный сценарий: [RUN_LOCAL.md](RUN_LOCAL.md).

## Возможности и границы прототипа

| Возможность | Реализация |
| --- | --- |
| Русский, казахский, смешанная речь | Локальный multilingual Whisper small, faster-whisper, CPU INT8; авто или явный выбор RU/KK |
| Микрофон и звук браузера/конференции | Две дорожки WASAPI, PCM WAV, сведение с ресемплингом и защитой от перегрузки |
| Загрузка аудио/видео | MP3/WAV/M4A/OGG/FLAC/WebM/MP4 через локальный HTTP API; декодирование PyAV |
| Поручения и сроки | Правила RU/KK, исходная цитата; неизвестные поля помечаются явно; нужен просмотр человеком |
| Саммари | Выдержки из распознанной речи, найденные решения и риски |
| Экспорт | DOCX/PDF с реестром поручений и стенограммой, TXT, локальная JSON-карточка СЭД |
| Диаризация | Акустическая диаризация пока отсутствует; текстовые метки говорящих сохраняются, личности по голосу не определяются |
| Zoom/Teams/Meet | Захват звука через системное устройство; бот-участник не реализован |
| Напоминания и промышленная СЭД | Не реализованы; JSON/XML экспорт не является готовой интеграцией |

Качество распознавания, особенно казахской и смешанной речи, зависит от записи и модели.
Система не гарантирует полноту выделения поручений. Неизвестные имена и сроки не должны
автоматически превращаться в официальные назначения без проверки секретарём.

## Приватность

Обработка аудио и текста выполняется на компьютере. Cloud fallback и вызовы OpenAI/Codex удалены.
Модель загружается только из локального каталога, `local_files_only=True`, Hugging Face offline включён.
Иконки и шрифты интерфейса локальные, HTTP-сервер слушает только `127.0.0.1`.
Модели скачиваются заранее при подготовке окружения; в закрытый контур переносится готовая папка.
В Git не должны попадать `.env`, ключи, аудиозаписи, протоколы, модели и сборки.

## Запуск из исходников

Python 3.11 x64, Windows:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\hf.exe download SYSTRAN/faster-whisper-small --revision 536b0662742c02347bc0e980a01041f333bce120 --local-dir models/whisper-small
.\.venv\Scripts\python.exe app.py
```

Для распознавания необходимы `model.bin`, `config.json`, `tokenizer.json`, `vocabulary.txt` в `models/whisper-small`.
Свой путь можно задать через `STT_MODEL_DIR`. Настройки CPU: `STT_DEVICE=cpu`, `STT_COMPUTE_TYPE=int8`.
При запуске из исходников данные по умолчанию находятся в `storage` проекта.
`QAZAQ_DATA_DIR` позволяет выбрать отдельный каталог данных для тестов.

## Сборка EXE

```powershell
.\.venv\Scripts\python.exe -m pip install "pyinstaller>=6,<7"
.\.venv\Scripts\python.exe build_portable.py
```

Спецификация: `QazaqProtocolLocal.spec`. Сборка включает native DLL и VAD-модель,
затем копирует Whisper рядом с EXE. Она не включает пользовательские записи или `.env`.
`build.bat` запускает тот же процесс. Старый `dist/QazaqProtocol.exe` относится к предыдущим сборкам.

## Архитектура

Рабочая сессия при запуске пустая. История открывается отдельной вкладкой с временем сохранения записи;
выбор записи открывает стенограмму и плеер. Экспорт TXT/DOCX/PDF/JSON использует системное окно «Сохранить как».
`core/audio_pipeline.py` ведёт независимые потоки live-распознавания (8 секунд) и обработки файлов
(20 секунд, включая короткий хвост). Загружаемые файлы образуют очередь, которая не блокирует новую запись.
Текущий интервал доступен для прослушивания до завершения его распознавания. Web Audio анализирует
реальный звук плеера для эквалайзера. Исходная запись остаётся на диске; задержка live зависит от CPU.
Источник можно заглушить во время записи; смена устройства требует остановки записи.

`app.py` — локальный API и окно WebView2; `ui/` — интерфейс, реальные уровни звука,
этапы обработки и история. `core/audio_recorder.py` управляет жизненным циклом WASAPI
и последовательно выполняет обращения к PortAudio, предотвращая гонку инициализации.
`core/stt_engine.py` распознаёт речь; `core/nlp_extractor.py` создаёт черновик протокола;
`core/export_service.py` формирует документы; `core/meeting_manager.py` хранит историю.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
```

Активные тесты используют синтетические данные и временные каталоги: STT/privacy,
конкурентный доступ к устройствам, жизненный цикл записи, сведение дорожек, RU/KK NLP,
multipart API, Unicode и длинные строки в документах. Старые облачные/демо-пробы
явно отключены через `SkipTest`, их секреты удалены.

Собранный EXE поддерживает отдельную сквозную диагностику:

```powershell
.\dist\QazaqProtocol-Local\QazaqProtocol.exe --self-test --audio "C:\demo\meeting.wav" --report "C:\demo\result.json"
```

Она проверяет реальную загрузку HTTP, локальную транскрипцию, сохранение истории и DOCX/PDF,
блокируя внешние подключения. Результат появляется в `result.json` после завершения.
`--ui-self-test <report.json>` открывает и закрывает тестовое окно WebView2,
проверяя Unicode, вкладки, кнопки и неподвижный визуализатор в тишине.

Проверено 23.09.2026 на двух локальных записях длительностью 206 и 274 секунды:
STT и экспорт успешны, внешних соединений во время диагностической обработки — 0.
Проверка не является оценкой точности распознавания и не подтверждает диаризацию.

## Публикация

Только вручную: `push_to_git.bat` или `python scripts/manual_push.py`.
Используется отдельный чистый checkout, а не старая локальная история с секретами.
`--prepare` только подготавливает исходники без коммита и отправки.
Для push нужна обычная авторизация Git Credential Manager. Токены в код не вставляются.
